# kz-climate

[![ci](https://github.com/mkbdlnv/kz-climate/actions/workflows/ci.yml/badge.svg)](https://github.com/mkbdlnv/kz-climate/actions/workflows/ci.yml)
[![publish](https://github.com/mkbdlnv/kz-climate/actions/workflows/publish.yml/badge.svg)](https://github.com/mkbdlnv/kz-climate/actions/workflows/publish.yml)

Теплеет ли в Алматы и Астане и насколько быстро. Проект берёт суточные данные реанализа ERA5 с 1940 года и считает по ним годовые аномалии, тренды и число экстремальных дней. Раз в месяц он сам обновляет данные и выпускает новый релиз.

**Дашборд:** https://climate.mkab.dev

## Как это работает

```
Open-Meteo (ERA5) ──fetch──► data/raw/<город>.csv ──check──► build ──► climate.json ──► GitHub Release
   суточные значения          снимок в git               проверки   анализ                  │
                                                                                            ▼
                                                    climate.mkab.dev забирает releases/latest/download/climate.json
```

1. **fetch** (`src/kzclimate/fetch.py`). При первом запуске скачивает всю историю с 1940 года частями по 5 лет, с паузами, чтобы не превысить лимит Open-Meteo. Дальше каждый раз заново скачивает только последние 120 дней: свежие дни ERA5 (ERA5T) предварительные и могут уточняться.
2. **check** (`validate.py`). Проверяет ряд: нет пропусков и дублей, значения физически правдоподобны, Tmin ≤ Tmean ≤ Tmax, источник не перестал обновляться. Если проверка не прошла, релиза нет и на сайте остаются прошлые цифры.
3. **build** (`indices.py`, `trend.py`, `report.py`). Считает годовые средние и аномалии, климатические нормы, счётчики экстремальных дней и тренды, и собирает `climate.json` (формат описан в [docs/data-format.md](docs/data-format.md)).

## Методика

- **Данные.** ERA5 — реанализ ECMWF/Copernicus с сеткой 0,25° (около 25 км), отданный через Open-Meteo. Используется только модель `era5` за весь период, без смешивания с другими источниками, чтобы в ряду не появилось ступеньки. Сутки считаются по местному времени (`Asia/Almaty`).
- **Год** входит в расчёт, только если в нём есть все дни. Текущий год не учитывается, пока не закончится.
- **Аномалия** — отклонение средней годовой температуры от среднего за 1961–1990. Это базовый период ВМО для оценки изменения климата, на нём же построены «полосы потепления». Последние месяцы сравниваются с нормой 1991–2020: это действующая стандартная норма ВМО.
- **Экстремальные дни** считаются по индексам ETCCDI: дни с морозом (FD, Tmin < 0 °C), дни без оттепели (ID, Tmax < 0 °C), летние дни (SU, Tmax > 25 °C), тропические ночи (TR, Tmin > 20 °C). К ним добавлены жаркие дни (Tmax ≥ 30 °C).
- **Тренд.** Тест Манна–Кендалла (с поправкой дисперсии на совпадающие значения и поправкой на непрерывность) отвечает на вопрос, есть ли монотонный тренд. Оценка наклона Тейла–Сена с 95 % интервалом показывает, насколько он крут. Оба метода ранговые: они не требуют нормальности и устойчивы к отдельным аномальным годам, поэтому стали стандартом для климатических рядов.

### Ограничения

- ERA5 — модель, усвоившая наблюдения, а не показания конкретной метеостанции. Ячейка 25 км сглаживает рельеф, а для Алматы у подножия гор это особенно заметно: абсолютные значения могут отличаться от станции на 1–2 °C. Тренды при этом надёжнее абсолютных значений.
- Ни один реанализ не учитывает городской остров тепла.
- Манн–Кендалл предполагает, что годы независимы. Автокорреляция годовых средних делает p-value несколько оптимистичным. Её учёт (поправка Хамеда–Рао или предварительное «выбеливание» ряда) — следующий шаг.
- До 1950-х годов наблюдений, которые усваивает ERA5, в регионе мало, поэтому ранние годы менее надёжны.

## Почему такие технологии

| | выбор | почему |
|---|---|---|
| язык | Python 3.12+ | стандарт научных вычислений. Для статистики есть проверенные библиотеки, а коллеги и проверяющие код прочтут |
| данные | pandas | суточные ряды, группировка по годам и месяцам, CSV |
| статистика | NumPy, SciPy | Манн–Кендалл написан сам (это несколько строк, и его проверяют тесты против `scipy.stats.kendalltau`). Наклон Сена с интервалом взят из `scipy.stats.theilslopes`, а не написан заново |
| HTTP | `urllib` из стандартной библиотеки | один GET-запрос не стоит лишней зависимости |
| источник | Open-Meteo | бесплатно, без ключа, весь ERA5 одним API. Альтернатива — Copernicus CDS: там нужен аккаунт, а данные приходят в NetCDF и это часы ожидания в очереди |
| результат | JSON в GitHub Release | у каждого релиза есть тег, коммит и неизменяемый файл. У «последнего» есть постоянный URL, поэтому дашборду не нужен доступ к репозиторию |
| тесты | pytest + pytest-cov | тесты на синтетических рядах с известным трендом и на настоящем ответе API из `tests/fixtures`. В сеть тесты не ходят |
| стиль | Ruff | один быстрый инструмент вместо flake8, isort и pyupgrade |
| CI/CD | GitHub Actions | живёт рядом с кодом, бесплатен для публичного репозитория, умеет запускаться по расписанию |

## CI/CD

- [`.github/workflows/ci.yml`](.github/workflows/ci.yml) — на каждый push и pull request: `ruff check` и `pytest` с покрытием на Python 3.12, 3.13 и 3.14.
- [`.github/workflows/publish.yml`](.github/workflows/publish.yml) — доставка данных:
  - **по расписанию** (8-го числа каждого месяца) скачивает новые дни. Если ничего не изменилось, на этом останавливается;
  - **при изменении кода** анализа (push в `main`, затрагивающий `src/`) пересчитывает результат по уже закоммиченным данным;
  - **вручную** (Run workflow), с флажком «скачать всю историю заново».

  Порядок шагов: тесты → загрузка → проверка → коммит снимка данных от имени бота → `build` → релиз `vYYYY.MM.DD-N` с `climate.json`, привязанный к этому коммиту. Если плановый запуск упал, workflow заводит issue.
- [`.github/dependabot.yml`](.github/dependabot.yml) — раз в месяц присылает PR с обновлениями пакетов и actions. CI проверяет каждый из них.

Любую опубликованную версию можно пересобрать: `git checkout <тег>` и `python -m kzclimate build`.

## Локально

Нужен Python 3.12 или новее.

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows; на Linux/macOS: source .venv/bin/activate
pip install -e ".[dev]"

pytest                          # тесты
ruff check .                    # стиль

python -m kzclimate fetch       # обновить data/raw (первый раз ~10 минут: вся история)
python -m kzclimate check       # проверить данные
python -m kzclimate build       # dist/climate.json
python -m kzclimate --city almaty build   # только один город
```

Новый город — одна строка в `src/kzclimate/cities.py`.
